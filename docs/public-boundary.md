# Public/Private Boundary

This repository documents Tyler Prime without publishing the personal appliance itself.

## Safe to publish

- High-level architecture and component responsibilities
- Sanitized diagrams and screenshots
- Design decisions and tradeoffs
- Honest implementation status
- Fictional task contracts, objects, events, and receipts
- General validation methods
- Lessons learned and build-journal entries

## Kept private

- Application source and internal packages
- Personal doctrine, identity prompts, and memory
- Credentials, tokens, account identifiers, and secrets
- Hostnames, private addresses, firewall rules, and network topology details
- Production workflow exports
- Real task receipts and conversation history
- Personal or market-account data
- Security-sensitive deployment configuration
- Third-party donor code that cannot be republished

## Publication checklist

Before adding an artifact:

1. Confirm that it contains no secrets or personal information.
2. Remove machine names, addresses, account details, and internal paths.
3. Replace real operational data with clearly marked fictional examples.
4. Confirm that the artifact does not reveal an avoidable attack surface.
5. Verify that every capability claim matches the running system.
6. Record whether the item is implemented, integrating, prototyped, or planned.
